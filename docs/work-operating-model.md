# Work operating model

## Ready

Work is ready when its goal, deliverables, scope, acceptance criteria, dependencies, path ownership,
and direct verification are explicit. Native blocked-by relationships are authoritative.

## Execution

Use one work package per change. Contract and structural work lands before consumers. Only
read-only evidence may run concurrently when tracked paths or decisions overlap.

## Done

A work package is done when its observable contract exists, focused checks and the maintained gate
pass, generated evidence is current, the diff is scoped, and recovery or failure behavior is tested.

## Delivery

Publication is a separate explicit action. A verified working tree does not imply authority to
commit, push, tag, publish artifacts, or mutate GitHub metadata.
